# VOID_LEAK_AUDIT.md

> Auditoria de "outros meios de vazar os menus originais" do Void Client (MCPE 0.15.10 VANILLA, `armeabi-v7a`, Thumb-2) — `libminecraftpe.so`.
> Síntese das 3 frentes (input alternativo / telas espontâneas / navegação a partir das nossas telas). Deduplicado. Todo achado ancorado em VA/símbolo real; inferência marcada `(a confirmar)`.
> Modelo mental: um vazamento é a UI nativa da Mojang **(1) recebendo input** por um caminho que não engolimos, ou **(2) renderizando/aparecendo** quando achamos que controlamos o contexto. Já fomos pegos uma vez — o menu MVC recebia toque pelo `ScreenViewAdapter`, caminho paralelo ao `handlePointer*`. Este documento cata todos os buracos análogos.

## 2. Fix recomendado em ordem

1. **BACK do Android (A1)** — primeiro. É o input alternativo mais provável de disparar hoje (toda tela tem BACK no A71) e bypassa 100% dos hooks de ponteiro. Hookar `nativeBackPressed` @0xdb58f0 + `nativeKeyHandler` @0xdb5ea4: com `g_uiAtiva`, não enfileirar e setar `g_backSolicitado` consumido em `my_update`. Cinturão: hook em `handleBack` @0x6cbdc8 (não chamar orig, retornar 1). **Regra de thread**: nunca chamar função do jogo direto do JNI — só flag.

2. **Classificador de contexto de 3 estados (C1)** — a reforma estrutural que fecha C2/A3/M4/M5/M6/B2/B3 de uma vez. Substituir o booleano `g_uiAtiva` por leitura do vptr de `*(scr+0x80)` contra a tabela OWN/TRANSIENTE/CEDER. Sem isso, cada tela espontânea continua virando flash ou soft-lock.

3. **Teardown de `g_screen` (M1)** — one-liner barato e independente, fecha o estado-zumbi das Opções: `if (g_screen==1 && !onMenu && !onPauseScreen) g_screen=0;` em `my_update`. Fazer junto do #2.

4. **Disconnect (C2)** — crítico pro perfil do Allan (dono de server, joga MP). Registrar `DisconnectScreenController` vptr `g_slide+0x16025d8` como CEDER-ACIONÁVEL no classificador (depende do #2). Mínimo seguro: hand-off limpo sem engolir o toque do "voltar".

5. **Button events MVC (A2)** — hookar `ScreenView::handleButtonEvent` @0x89f7ac (ou os adapters @0x8ac044/@0x8ac050), engolir com `g_uiAtiva`. Defesa em profundidade da mesma classe do bug já apanhado.

6. **Modais (A3)** — registrar `ModalScreenController` vptr `g_slide+0x1602b10` como CEDER-ACIONÁVEL; nunca cobrir silenciosamente (risco de soft-lock por ser acionável).

7. **Swallow incondicional (M3)** — travar press/release p/ engolir sempre que `g_uiAtiva` (hit-test só escolhe a ação). Verificação + possível correção pequena.

8. **Supressão de render do StartMenu (B1)** — hookar `ScreenView::setupAndRender` @0x89e2d0 gateado no vptr `StartMenuScreenController` (`g_slide+0x160323c`). Fecha a janela de startup/injeção. Reaproveita o mesmo mecanismo de supressão que o classificador já vai usar.

9. **`handleMenuButtonPress/Release` (M2)** — hook @0x6c34dc/@0x6c361c; ou já coberto por A1 no nível JNI.

10. **Toasts / Progress / Sign-in (M4/M5/M6)** — entram "de graça" quando o classificador do #2 ganhar as entradas TRANSIENTE e CEDER.

11. **Death / Realms (B2/B3)** — baixa frequência; cobrir no classificador por completude.

12. **Diálogo Android nativo (A4)** — decidir por caso: hookar `AppPlatform_android::showDialog` @0xdb0a88 p/ impedir, ou documentar como fora de escopo (nenhum overlay GL cobre janela Android).

13. **Texto/IME (M7)** — adiar até telas Void reusarem textbox nativo ou coexistirem com chat/campo focado.

## 3. O que NÃO vaza (confirmado seguro)

- **Multi-toque / 2º dedo** — entradas de ponteiro são single-pointer por design na 0.15: `handlePointerPressedButtonPress()`/`Release()` e `handlePointerLocation(short,short)` sem argumento de id; `Screen::handlePointerPressed(bool)` @0x863ac4 opera 1 ponteiro. Dedos extras vão p/ TouchControls de gameplay, suprimidos quando há tela com `Screen::absorbsInput` @0x8639d0 ativa. *(Ressalva: confirmar `absorbsInput=1` no contexto das NOSSAS telas — nas nativas o engine já seta.)*
- **Mouse / scroll wheel** — não há entrypoint JNI de mouse/scroll neste build Android; `nativeKeyHandler` @0xdb5ea4 só processa keyCode==4; não existem `nativeMouse`/`nativeScroll`. `handleScrollWheel` (`Screen` @0x863a68, `OptionsScreen` @0x856f28) e `ScrollingPane::handleMouseInput` @0x6ea99c existem mas sem fonte de HW no A71. Scroll da nossa UI vem de drag = `handlePointerLocation` (já hookado).
- **`nativeKeyHandler` para teclas != BACK** — retorna 0 sem despachar nada (@0xdb5ea6 `cmp r2,#4; ittt ne; return 0`). Sem teclado de HW genérico chegando ao engine por Java.
- **`ScreenViewAdapter::handlePointerPressed(bool)` @0x8ac0dc** (corpo `bx lr`, vazio) e **`handleBackEvent(bool)` @0x8ac0e0** (retorna 0) — não são caminhos independentes: o press MVC vem pelo caminho clássico já hookado e o back do adapter é no-op.
- **Input do toast não é buraco separado** — enquanto o overlay segue ligado (`g_uiAtiva=1`), o swallow em `handlePointerPressedButtonPress` @0x6c170c já engole o consumidor `ToastManager` (MC+0x214). O problema só existe porque o gate CAI; corrigido o gate (TRANSIENTE), o input já fica engolido.
- **`CubemapBackgroundScreen`** (fundo panorâmico) renderiza ATRÁS do StartMenu e é coberto pela sidebar opaca do Void — não vaza por cima.
- **`ChooseLevelScreen` clássica** (lista de mundos legada, vtable 0x1601f50) existe no binário mas o menu MVC não a usa; não surge espontânea.
- **Nossas Opções SOBRE o pause → "Voltar"** — NÃO cai em tela nativa. `g_screen=1` é overlay puro; nenhuma `OptionsScreen` nativa empilhada (`vc_open_options`@L403 é código morto). PauseScreen clássica (0x1605954) permanece no topo SUPRIMIDA por `my_pauseRender`; "Voltar" (`h_release`@L622) faz `Options::save` @0x927c74 + `g_screen=0` → volta pro overlay de pause. Nenhuma tela Mojang aparece.
- **Volta ao menu custom** (back da PlayScreen / após LeaveLevelScreen) — não pisca StartMenu nativo. `my_apSwap` reavalia `onMenu` ao vivo na render-thread e compõe o quad opaco dentro do MESMO `AppPlatform::swapBuffers` antes do present; o menu nativo nunca é apresentado isolado no fluxo de navegação.
- **Pause → "Sair" → `setLeaveLevelScreen` @0x87530c** — REPLACE confirmado no disasm (solta refcounts de pause+InGame). `LeaveLevelScreen::render` @0x832fdc preenche PRETO OPACO (`Color{0,0,0,1}` @0x832ff4-0x833000); `renderGameBehind` @0x832fd8 retorna 0; visível ~2 ticks (`tick` @0x83301c só na 2ª passada descarrega o nível e tail-calla `setStartMenuScreen` @0x866bd0).
